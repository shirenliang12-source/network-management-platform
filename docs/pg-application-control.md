# 内置 PG 与 Windows 应用控制

已确认的本机问题：捆绑 initdb.exe 无 Authenticode 签名，CodeIntegrity 日志 3077/3033 记录了执行拦截。源码修复不等于已解决此二进制的信任问题。

## 修复后的安装行为

- 对新安装执行 initdb、postgres、pg_ctl、pg_dump 的 `--version` 预检查，首次失败即停止，不重试、不改路径、不改安全策略。
- 预检查通过前不创建密码、PG 数据目录或修改数据库连接。
- 预检查被应用控制阻止时返回专用退出码 20，显示安全诊断；安装器允许用户明确选择保留 SQLite 继续升级，默认/无人值守取消。
- 如果已经进入初始化或迁移阶段，错误仍按失败回滚处理，不使用上述继续分支。
- 无 PG 服务且从未创建数据目录的旧 recovery.json 会移到同一受保护目录内的 recovery-uninitialized-随机值.json；内容不输出、不删除。只在预检查通过后处理。
- 任何现有/部分初始化的数据目录或现有服务均保留，拒绝自动重新初始化。不能据此任意删除 ProgramData 下的 PG 数据。

## 仍需要部署方解决

内置 PG 要真正运行，必须使用系统接受的发行包/可信签名，或由安全管理员按组织策略批准。仅给外层安装器签名不代表内部 EXE/DLL 自动获准。不能保证更换官方安装器就能通过。

版本查询只验证基本执行能力，不能保证运行时所有 DLL、子进程和服务身份都通过策略。源码回归采用模拟拦截，未绕过或重新运行已被拦截的 initdb，完整 PG 迁移仍待允许执行的测试机验证。

本修复尚未重新生成安装包；已交付的 v1.9.53/v1.9.54 安装包不会自动获得这些改动。
